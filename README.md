# wiki-revert-audit

Which reverts count? Reverter populations, attribution rules and observation windows behind a Wikipedia indicator of information quality work.

Current manuscript, supplement and cover letter: `05_manuscript/` (v0.13). Supplement tables are generated by `03_pipeline/17_supplement_v13.py` from `04_output/`. Archived releases: https://doi.org/10.5281/zenodo.24054641 (all versions).

Sole-author measurement audit (Hongwon Jeong, Hanyang University ERICA). Fixed-anchor design: the same newcomer edits are held constant while the set of revisions that count as a revert (all / excluding bots / excluding bots and tools) and the observation window (24 h / 7 d / final state) are varied. Data: Wikimedia `mediawiki_history` monthly dumps. Code and aggregates are released on GitHub and archived on Zenodo (release v1.0.0: https://doi.org/10.5281/zenodo.24054642; all versions: https://doi.org/10.5281/zenodo.24054641; preregistration: https://doi.org/10.5281/zenodo.23720117); no OSF.

Pipeline: `03_pipeline/README.md`. Design and preregistration draft: `02_plan/`. Korean working documents: `00_START_HERE.md`, `01_context/`.

License: MIT (code). Documents CC BY 4.0 after publication.

## Reproducing the results

Two paths are distinct.

1. From the released aggregates to the tables and figures (always possible). `python3 03_pipeline/17_supplement_v13.py` regenerates the supplement tables, and the tables of the article, from `04_output/`; `python3 03_pipeline/16_figures_revision.py` regenerates the figures from `04_output/fig_data_*.csv`. Requirements: `03_pipeline/requirements.txt`.
2. From the dumps to the aggregates (possible only while `mediawiki_history` version 2026-09 is hosted by Wikimedia, or from a private copy). Order: `00_download_dump.sh`, `02_extract_pass1.py`, `03_build_anchor_table.py` (sampling seed 20261026), `06_recompute_reverts_d3.py`, `04_audit_grid.py`, `09_robustness.py`, `14_successor_decomposition.py`, `18_stream_extract.py`, `15_revision_tables.py`, then scripts 19 to 26. Editor-level derived files (`02_derived/`) are not released because they can be re-identified from public edit histories.

`26_attribution_validation.py` also checks the 15-revision radius rule against python-mwreverts on synthetic page histories, which needs no dump.
